Actúa como arquitecto senior de software especializado en CodeIgniter 4, diseño modular, sistemas extensibles tipo WordPress, migraciones de base de datos y arquitectura multiaplicación.

Tengo una plataforma base desarrollada en CodeIgniter 4 y deseo convertirla en una arquitectura extensible tipo WordPress, donde la plataforma principal funcione como núcleo del sistema y permita instalar, activar, desactivar, actualizar y desinstalar componentes adicionales.

El objetivo es que estos componentes funcionen como aplicaciones o módulos independientes que puedan agregarse a la plataforma sin afectar las tablas, rutas, controladores, modelos, vistas, permisos ni configuraciones base del sistema.

Necesito que diseñes una propuesta técnica completa para implementar esta arquitectura modular en CodeIgniter 4.

La solución debe contemplar lo siguiente:

* Componentes independientes ubicados en una carpeta específica.
* Separación clara entre código base y código de cada componente.
* Capacidad de activar o desactivar componentes sin eliminar su información.
* Capacidad de instalar o desinstalar componentes desde un panel administrativo.
* Capacidad de registrar rutas, vistas, controladores, modelos, helpers, servicios y migraciones propias de cada componente.

4. Prefijos de tablas por componente

Diseñar una estrategia para que cada componente tenga sus propias tablas adicionales sin chocar con las tablas base de la plataforma.

La plataforma base ya cuenta con tablas principales del sistema, por lo tanto, los componentes no deben modificar directamente esas tablas salvo que sea estrictamente necesario.

Cada componente debe crear sus tablas usando un prefijo propio, por ejemplo:

* Sistema base: core_, sys_ o app_
* Componente de facturación: cmp_fact_
* Componente de encuestas: cmp_enc_
* Componente de cartera: cmp_cart_
* Componente de eventos: cmp_evt_
* Componente de inventario: cmp_inv_

La estrategia debe incluir:

* Convención de nombres de tablas.
* Convención de nombres de campos.
* Uso de claves primarias.
* Uso de claves foráneas hacia tablas base cuando sea necesario.
* Reglas para evitar colisiones entre componentes.
* Reglas para evitar que un componente sobrescriba tablas de otro.
* Validación previa antes de ejecutar migraciones.
* Registro de tablas instaladas por cada componente.
* Manejo de rollback o desinstalación segura.
